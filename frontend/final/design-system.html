Pages — Voice Stamp
Doctors record a 3–5 s voice sample used by SONIOX to identify their speaker index automatically in every session. Recorded once per user on setup or from Settings.
VoiceStampPage /voice-stamp
Co-located: VoiceRecorder · WaveformDisplay · StampCard
How voice stamps work
1.Doctor records 3 s phrase on account setup
2.Stamp audio uploaded to Supabase Storage
3.Backend enrolls stamp with SONIOX speaker ID API
4.During sessions, SONIOX diarizes by that speaker ID
5.Transcript entries auto-tagged with doctor's name

System Architecture
Two-service split: React SPA on any CDN (UI only) + dedicated backend on Render (auth, API, WebSocket proxy). All secret keys live exclusively on Render — the browser never touches them.

Authentication Flow
Auth lives entirely on the Render backend. The React SPA uses a useAuth() hook + Zustand auth.store to guard routes client-side — the backend verifies the JWT on every API call. Roles: admin · trauma_lead · nurse · paramedic · viewer
sequenceDiagram
  actor User
  participant Browser as Browser (React SPA)
  participant Store as auth.store (Zustand)
  participant Backend as Render Backend
  participant DB as Supabase PostgreSQL

  Note over User,DB: ── Login ──
  User->>Browser: Submit LoginForm (email + password)
  Browser->>Backend: POST /auth/login
  Backend->>DB: SELECT user WHERE email = ?
  DB-->>Backend: user row + hashed password
  Backend->>Backend: bcrypt.verify(password, hash)
  Backend-->>Browser: { jwt, user, role }
  Browser->>Store: auth.store.setUser({ jwt, user, role })
  Store->>Browser: navigate('/')

  Note over User,DB: ── Protected route ──
  User->>Browser: Navigate to /session/:id
  Browser->>Store: useAuth() reads auth.store
  alt token present
    Store-->>Browser: render SessionPage
    Browser->>Backend: GET /incidents/:id (Bearer JWT)
    Backend->>Backend: verify JWT signature
    Backend-->>Browser: incident data
  else no token
    Store-->>Browser: navigate('/login')
  end

  Note over User,DB: ── WebSocket auth ──
  Browser->>Backend: WS /ws/room/:id?token=JWT
  Backend->>Backend: Verify JWT before upgrading
  Backend-->>Browser: WS connection open

Tech Stack
Chosen for developer velocity, real-time capability, and Israeli healthcare constraints (data residency).
⚛️FrontendReact SPA · Vite
  • • React 19 + Vite — SPA, no SSR, deployed as static bundle
  • • React Router v7 — client-side routing, protected route wrappers
  • • Zustand — auth.store, session.store, theme.store
  • • Tailwind CSS 4 + design tokens (CSS custom properties)
  • • React Hook Form + Zod — MoH form validation
⚙️Render BackendNode / Express
  • • Express.js — REST API (auth, incidents, summary endpoints)
  • • ws library — WebSocket server for SONIOX proxy
  • • Always-on Render Web Service — no cold-start for live WS connections
  • • Holds all secret keys: SONIOX, Anthropic, DB connection strings
🗄️Database
  • • Supabase — PostgreSQL for structured data (users, incidents, summaries)
  • • MongoDB — transcript chunks (high-frequency writes, document model)
  • • Row-Level Security — hospital data isolation on Supabase
  • • Supabase Realtime — coarse room-state events (timers, form locks); live transcript chunks are broadcast directly by Render WS
🎙️Transcription
  • • SONIOX API — WebSocket, Hebrew + English, speaker diarization
  • • Proxied via Render WS proxy — SONIOX key never touches the browser
  • • Chunks stored in MongoDB → broadcast via Supabase Realtime to all room clients
  • • Audio optionally stored in Supabase Storage for audit trail
🤖AI / Summary
  • • Claude API (claude-sonnet-4-6) — auto-fill MoH form from transcript
  • • Called from Render backend only — API key never in frontend
  • • Structured output with tool use → maps directly to form schema
  • • Prompt caching for protocol definitions (saves tokens); runs on incident close
🔒Auth & Security
  • • Custom JWT issued by Render backend — email/password, hospital SSO optional
  • • JWT stored in auth.store (Zustand + localStorage); verified by Render on every API call
  • • RBAC: 5 roles (admin / trauma_lead / nurse / paramedic / viewer)
  • • All sign-offs stored with user_id + timestamp; API keys live only on Render
🚀Deployment
  • • React SPA — static bundle deployed to any CDN (Vercel, S3, Netlify)
  • • Render — dedicated backend (Node/Express), always-on WebSocket support
  • • Supabase can be self-hosted for Israel data residency
  • • CI/CD: GitHub Actions → build web/ → deploy static + deploy api/ to Render
Folder Structure
Two-root repo: web/ → React SPA (any CDN) · api/ → Render Node/Express. All secret keys live only in api/.env. No monorepo overhead — types live in web/src/shared/types/ and are duplicated into api/src/types/ (or extracted to a shared package later if drift becomes a problem).

web/src/pages/session/services/keyword.service.ts pure TS — zero React, zero imports from stores
const PROTOCOL_KW = ['החייאה', 'CPR', 'cardiac arrest', 'ACLS', 'VF'] const TIMER_KW: Record<string, number> = { 'אדרנלין': 240, // epinephrine → 4 min timer 'אמיודרון': 300, // amiodarone → 5 min timer 'epinephrine': 240, } export function detectKeywords(text: string): KeywordEvent[] { const lower = text.toLowerCase() const events: KeywordEvent[] = [] for (const kw of PROTOCOL_KW) if (lower.includes(kw.toLowerCase())) events.push({ type: 'open_protocol', keyword: kw }) for (const [kw, secs] of Object.entries(TIMER_KW)) if (lower.includes(kw.toLowerCase())) events.push({ type: 'start_timer', keyword: kw, durationSec: secs }) return events }

export class WSService { private ws: WebSocket | null = null private url = '' private onMsg: (data: string) => void = () => {} connect(url: string, onMessage: (data: string) => void) { this.url = url; this.onMsg = onMessage this.ws = new WebSocket(url) this.ws.onmessage = e => this.onMsg(e.data) this.ws.onclose = () => setTimeout(() => this.connect(this.url, this.onMsg), 2000) } send(data: ArrayBuffer | string) { this.ws?.send(data) } disconnect() { this.ws?.onclose = null; this.ws?.close() } } export const wsService = new WSService() // singleton — one WS per session

Coupling Risk Assessment
✓
JWT auth — client-side guard via Zustand, server-side verify per call
The React SPA keeps the JWT in auth.store (Zustand, persisted to localStorage). useAuth() reads the store and redirects to /login if no token — client-side only. The Render backend independently verifies the JWT signature on every API call. No shared secret needed in the frontend bundle.
✓
Transcript broadcast — direct WS, not Supabase Realtime
Render's soniox-proxy.ts keeps a rooms: Map<incidentId, Set<WebSocket>>. When a SONIOX chunk arrives it writes to MongoDB and fans out directly to all WebSockets in that room. No Supabase Realtime hop needed for live chunks (saves latency + cost). Supabase Realtime is used only for coarser room-state events (timer updates, form field locks).
✓
No server-side API routes in frontend — pure SPA
All sensitive server logic (SONIOX proxy, Claude call, incident writes) lives on Render. The React SPA calls Render via shared/api/client.ts (typed fetch wrapper, base URL from VITE_BACKEND_URL). There is no server-side execution in the web bundle — secrets can only ever be in api/.env.
✓
Page components co-located — no import leakage between pages
Domain components (e.g. ProtocolPanel/, MoHForm) live inside pages/session/components/ — never imported by other pages. Generic UI (buttons, modals, badges) lives in components-ui/ — never imports page logic. This boundary prevents tangled cross-page dependencies as the codebase grows.
✓
Type drift managed — web/src/shared/types/ mirrored in api/src/db/schema.ts
Types are duplicated between web/src/shared/types/ and api/src/db/schema.ts rather than a shared package — simpler to start. When drift becomes a real problem (new field breaks both services), extract to a local packages/types/ pnpm workspace. Until then, keep it simple.
!
Watch: Render cold-start on free tier kills live WS
Render's free tier spins down after 15 min of inactivity. A cold-start takes ~30s — fatal for a live trauma session. Mitigation: use Render's paid "Always On" flag (Starter plan, ~$7/mo) or implement a lightweight health-check ping from the frontend every 10 min to prevent spin-down during an active shift.
